# Before You Start

Before making changes:

1. Fork the repository.

2. Create a feature branch.

3. Keep changes focused.

4. Test everything.

5. Update documentation if needed.

6. Submit a Pull Request.

---

# Development Workflow

Clone repository

```bash
git clone https://github.com/CryptoTengo/PanjoCoin.git
```

Create branch

```bash
git checkout -b feature/my-feature
```

Commit

```bash
git commit -m "feat: add staking interface"
```

Push

```bash
git push origin feature/my-feature
```

Open Pull Request.

---

# Branch Naming

Please use the following format.

Features

```
feature/description
```

Bug fixes

```
fix/description
```

Documentation

```
docs/description
```

Refactoring

```
refactor/description
```

Testing

```
test/description
```

Hotfix

```
hotfix/description
```

Examples

```
feature/liquidity-dashboard

fix/erc20-transfer

docs/tokenomics-update

test/staking-contract
```

---

# Commit Message Guidelines

We use Conventional Commits.

Examples:

```
feat: add liquidity locker

fix: correct transfer tax calculation

docs: update roadmap

refactor: optimize gas usage

test: add unit tests

style: improve formatting

build: update dependencies

chore: cleanup repository
```

---

# Pull Request Process

Each Pull Request should:

- have a clear description
- solve one specific issue
- include screenshots if UI changed
- include tests when applicable
- update documentation if required

Small PRs are preferred over very large ones.

---

# Coding Standards

## Solidity

Follow:

- Solidity Style Guide
- OpenZeppelin best practices
- Checks-Effects-Interactions pattern

Requirements:

- SPDX license
- NatSpec comments
- Events for state changes
- Custom errors when appropriate
- Minimal gas usage

---

## JavaScript / TypeScript

Use:

- ESLint
- Prettier

Avoid:

- unnecessary complexity
- duplicated code

---

## HTML/CSS

Keep code:

- semantic
- responsive
- accessible

---

# Testing

All new code should be tested whenever possible.
